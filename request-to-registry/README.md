# Заявка с сайта попадает в систему учёта

Самостоятельная демонстрация с вымышленными данными. Система учёта тестовая, записи хранятся в памяти локального API до остановки сервера.

## Запуск

Открой терминал в папке примера и выполни `node server.cjs`. Открой [форму на локальном сервере](http://127.0.0.1:8766/). Сервер принимает соединения только с этого компьютера. Для остановки нажми Ctrl+C. Для нового прогона с пустым списком останови и снова запусти сервер. Для запуска нужна Node.js, пакеты устанавливать не нужно.

1. **Обычная отправка.** На пустом сервере отправь форму с заполненными тестовыми данными. Появится заявка REQ-001, счётчик покажет одну запись.
2. **Повтор той же заявки.** Нажми «Отправить ещё раз». Форма покажет тот же номер, счётчик останется на единице.
3. **Сбой и повтор.** Перезапусти сервер и обнови форму. Отметь «Имитировать сбой подтверждения» и отправь заявку. API сохранит запись, но вернёт HTTP 503 вместо подтверждения. Форма сообщит об ошибке. Нажми «Повторить отправку». Подтвердится та же запись REQ-001, счётчик покажет одну запись.

Форма использует один ключ для всех попыток отправить эту заявку. Новая страница формы создаёт новый ключ. После перезапуска локальный API начинает с пустого списка.

## Результаты проверок

Команда `node --test server.test.cjs` на Node.js 24.22.1. Прошли 4 теста, включая одновременный повтор и попытку использовать тот же ключ с изменёнными данными (HTTP 409).

| Сценарий | Ответ API | Записей в учёте |
| --- | --- | --- |
| Обычная отправка | HTTP 201, REQ-001 | 1 |
| Повтор той же заявки | HTTP 200, REQ-001 | 1 |
| Сбой после сохранения | HTTP 503, форма предлагает повтор | 1 |
| Повтор после сбоя | HTTP 200, REQ-001 | 1 |

Сценарии проверены в Chrome на ширинах 390 и 1440 px. Запись сверена через `GET /api/requests`.
